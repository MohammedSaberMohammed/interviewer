## Why Teams Care

Choose declarations, expressions, and arrows based on hoisting, naming, stack traces, and this behavior. Function behavior becomes visible when callbacks run later, methods are passed around, or a helper accidentally keeps old state alive. The useful answer is the one that predicts the next bug before it ships.

## Code Shape

```javascript
run();
function run() {
  return 'available before this line';
}
```

Prefer the version a teammate can modify safely during an incident or late-stage review.

## Readiness Check

- Name the variables the function closes over.
- Pick arrow or regular function based on this binding.
- Keep callback side effects obvious and test the logic around them.
