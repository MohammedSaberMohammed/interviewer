## Where It Breaks

Review JavaScript changes for unsafe HTML, token exposure, open redirects, dependency risk, and missing validation. Security issues in JavaScript often come from treating strings, origins, packages, or tokens as more trustworthy than they are. The practical test is whether another engineer can predict the behavior from the code shape.

## Ship This Shape

```javascript
const result = input == null ? fallback : transform(input);
```

Choose names and structure that preserve the business rule, not just the shortest syntax.

## Review Pass

- Trace source to sink before approving DOM changes.
- Avoid script-readable storage for sensitive credentials.
- Review dependency and CSP changes as part of the feature.

<Callout type="senior">
Security answers should be concrete: name the source, the sink, the attacker-controlled value, and the safer API.
</Callout>
