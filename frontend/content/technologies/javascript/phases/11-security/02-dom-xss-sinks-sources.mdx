## Where It Breaks

Identify attacker-controlled sources and dangerous sinks before code reaches production. Security issues in JavaScript often come from treating strings, origins, packages, or tokens as more trustworthy than they are. The useful answer is the one that predicts the next bug before it ships.

## Ship This Shape

```javascript
element.textContent = userInput; // safe text sink
// Avoid innerHTML for untrusted values.
```

Prefer the version a teammate can modify safely during an incident or late-stage review.

## Review Pass

- Trace source to sink before approving DOM changes.
- Avoid script-readable storage for sensitive credentials.
- Review dependency and CSP changes as part of the feature.

<Callout type="senior">
Security answers should be concrete: name the source, the sink, the attacker-controlled value, and the safer API.
</Callout>
