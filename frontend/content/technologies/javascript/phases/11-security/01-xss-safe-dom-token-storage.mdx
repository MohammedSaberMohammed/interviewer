## The Default: Text, Not HTML

```javascript
message.textContent = userInput;
```

This displays user input as text. It does not execute markup.

Avoid this unless the HTML is trusted and sanitized:

```javascript
message.innerHTML = userInput;
```

## Common DOM XSS Shape

```javascript
const name = new URLSearchParams(location.search).get('name');
document.querySelector('#welcome').innerHTML = `Welcome ${name}`;
```

An attacker can put markup or script-capable payloads in the URL. Prefer safe sinks:

```javascript
const name = new URLSearchParams(location.search).get('name') ?? 'friend';
document.querySelector('#welcome').textContent = `Welcome ${name}`;
```

## Token Storage Is a Tradeoff

Local storage is easy to use but readable by JavaScript. Cookies can be `HttpOnly` so scripts cannot read them, but they need CSRF-aware design. There is no storage choice that makes XSS harmless.

<Callout type="critical">
The strongest XSS habit is not "sanitize somewhere." It is using safe APIs by default, validating at boundaries, escaping in the right context, and adding CSP as defense in depth.
</Callout>
