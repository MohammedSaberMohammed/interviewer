## Failure Mode

Keep interaction responsive by breaking up work and moving heavy computation away from the main thread. Slow JavaScript blocks interaction; leaked references make sessions degrade the longer users keep the app open. Keep the explanation tied to behavior you can observe in a debugger, test, or production incident.

## Working Pattern

```javascript
setTimeout(() => processNextChunk(queue), 0);
```

Keep the implementation explicit enough that ownership, failure, and the next likely change are easy to see.

## What To Verify

- Measure the bottleneck before changing code.
- Reduce initial JavaScript and defer non-critical work.
- Remove references that outlive their screen, request, or component.
