## When You Reach For It

Translate HTTP responses into useful user states and developer diagnostics. These flows combine user intent, server truth, transient failures, and data that may survive after the tab closes. Keep the explanation tied to behavior you can observe in a debugger, test, or production incident.

## Concrete Pattern

```javascript
if (response.status === 401) redirectToLogin();
if (!response.ok) throw new Error('Request failed');
```

Keep the implementation explicit enough that ownership, failure, and the next likely change are easy to see.

## Trap To Avoid

- Check response.ok instead of assuming fetch rejects on HTTP errors.
- Keep request state explicit in the UI.
- Store only values that are safe to expose to page scripts.
