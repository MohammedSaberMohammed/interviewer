## Node Is Great at I/O, Not Blocking CPU Work

Node can handle many concurrent I/O operations because file, network, and timer work does not block the JavaScript call stack. CPU-heavy work can still block the process.

```javascript
// Bad in a request handler if the input can be huge
const result = expensiveSynchronousCalculation(payload);
```

Move heavy work to a worker, queue, database, or service designed for it.

## Validate Configuration at Startup

```javascript
function requireEnv(name) {
  const value = process.env[name];

  if (!value) {
    throw new Error(`Missing required environment variable: ${name}`);
  }

  return value;
}

export const config = {
  databaseUrl: requireEnv('DATABASE_URL'),
  nodeEnv: process.env.NODE_ENV ?? 'development',
};
```

Failing fast is better than discovering missing config during the first customer request.

## Request Handlers Need Boundaries

```javascript
app.post('/orders', async (req, res, next) => {
  try {
    const order = await createOrder(req.body);
    res.status(201).json(order);
  } catch (error) {
    next(error);
  }
});
```

Centralized error middleware can map known errors to HTTP statuses, log unexpected errors, and avoid leaking internals to clients.
