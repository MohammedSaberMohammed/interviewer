## Why Teams Care

Handle the values that break real applications: floating-point math, date parsing, time zones, and user-facing formatting. A small assumption here can corrupt state, hide valid user input, or make an API response look safer than it is. Anchor the concept in the runtime effect: what changes, what waits, what mutates, or what becomes unsafe.

## Code Shape

```javascript
const formatter = new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' });
formatter.format(19.99);
```

Write the code so the boundary is obvious: what comes in, what can fail, and what leaves the function.

## Readiness Check

- Confirm the actual runtime type before leaning on syntax.
- Default missing values without replacing valid falsy values.
- Normalize external data once, close to the boundary.
