## Where It Breaks

Read dependency intent and avoid shipping test tools or duplicating framework versions by accident. Module and build decisions affect what code ships, when it loads, and whether production behaves like local development. Use the concept to narrow the failure mode, not to recite trivia.

## Ship This Shape

```javascript
// dependencies: code needed at runtime
// devDependencies: build, lint, and test tools
```

Leave the code in a shape that is easy to test at the behavior boundary.

## Review Pass

- Separate build-time replacement from runtime configuration.
- Know which dependencies are shipped to users or servers.
- Use code splitting where delayed loading improves startup.
