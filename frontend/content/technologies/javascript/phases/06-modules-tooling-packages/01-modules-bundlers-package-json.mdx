## ES Modules Are the Default Mental Model

```javascript
// math.js
export function add(a, b) {
  return a + b;
}

// app.js
import { add } from './math.js';
```

ES module imports are static, which helps tools analyze dependencies, split bundles, and remove unused exports.

## Dynamic Import Loads Later

```javascript
button.addEventListener('click', async () => {
  const { openChart } = await import('./chart.js');
  openChart();
});
```

This keeps heavy chart code out of the initial page load.

## Read `package.json` Like a Maintainer

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "test": "vitest"
  },
  "dependencies": {
    "zod": "^4.0.0"
  },
  "devDependencies": {
    "vite": "^7.0.0",
    "vitest": "^3.0.0"
  }
}
```

Runtime packages go in `dependencies`. Build and test tools usually go in `devDependencies`.

<Callout type="info">
Modern surveys consistently show Vite and Vitest as prominent choices because teams care about fast local feedback. You do not need to memorize every bundler, but you should know what bundlers solve: module resolution, transpilation, code splitting, optimization, and environment replacement.
</Callout>
