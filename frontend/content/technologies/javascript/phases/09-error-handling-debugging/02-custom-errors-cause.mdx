## Why Teams Care

Add context without losing the original failure by using error classes and cause. Bad error handling either hides the cause or crashes too far away from the real failure. Anchor the concept in the runtime effect: what changes, what waits, what mutates, or what becomes unsafe.

## Code Shape

```javascript
if (response.status === 401) redirectToLogin();
if (!response.ok) throw new Error('Request failed');
```

Write the code so the boundary is obvious: what comes in, what can fail, and what leaves the function.

## Readiness Check

- Catch only where you can add context, recover, or report.
- Keep the original error available through cause or structured logging.
- Turn fixed bugs into tests when the behavior is important.
