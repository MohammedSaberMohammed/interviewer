## Catch Where You Can Do Something Useful

```javascript
async function saveProfile(profile) {
  try {
    return await api.put('/profile', profile);
  } catch (error) {
    throw new Error('Could not save profile', { cause: error });
  }
}
```

Adding context is useful. Catching only to log and continue can hide a broken state.

## Always Await or Return Promises

```javascript
async function handler() {
  await sendEmail(); // errors can be caught by the caller
}
```

If you intentionally fire and forget, attach a catch and make that decision obvious.

```javascript
void sendAnalytics().catch((error) => {
  console.error('Analytics failed', error);
});
```

## Debugging Checklist

1. Reproduce the bug with the smallest input.
2. Read the first meaningful stack frame in app code.
3. Inspect runtime values, not assumptions.
4. Add a regression test when the bug is understood.

<Callout type="senior">
The difference between junior and senior error handling is boundaries. UI code should show a useful state, API code should return a meaningful status, and background work should report failures without crashing unrelated work.
</Callout>
